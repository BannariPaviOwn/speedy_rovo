## Getting Started

First, run the development server:

```bash
npm run dev
```

Open [http://localhost:3000/login](http://localhost:3000/login) for sign-in (recommended entry in dev).

- **`GET /`** — redirects to `/login` (no app shell compile). After sign-in, middleware sends staff to `/slots`.
- Auth for the app shell is hydrated **client-side** in `RoleProvider` so the `(app)` layout does not block on Supabase during compile.
- **`/slots`** — schedule grid loads in a separate client chunk (`next/dynamic`) so Turbopack dev compile stays fast.

### Windows CMD (not PowerShell)

If `npm run dev` sticks on `○ Compiling /slots ...`, stop the server (Ctrl+C), then:

```cmd
cd /d D:\projects\speedy\speedy_rovo
taskkill /F /IM node.exe
rmdir /s /q .next
npm run dev
```

> **Warning:** `taskkill /F /IM node.exe` ends **all** Node processes on this PC (other dev servers, tools, etc.).

Then open **http://localhost:3000/login** first (not `/` or `/slots` on a cold start). Navigate to Schedule after sign-in.

Production check:

```cmd
npm run build
```

If dev ever hangs on `Compiling /` or `/slots`, clear `.next` as above and use `/login` first; `npm run build` should complete without errors.

### Auth cookies & staff roles (troubleshooting)

After a successful sign-in at **http://localhost:3000/login**, Application cookies for `localhost` should include one or more `sb-<project-ref>-auth-token` chunks (not only `__next_hmr_refresh_hash__`).

If sign-in “works” but schedule shows no role or the console logs `[fetchStaffContext] no staff_roles row for user`:

1. **Sign out** (profile menu → Sign out).
2. **Clear site data** for `localhost:3000` (DevTools → Application → Storage → Clear site data).
3. Open **http://localhost:3000/login** and sign in again (do not bookmark `/slots` for the first load).
4. In DevTools → Application → Cookies → `http://localhost:3000`, confirm `sb-*-auth-token*` cookies exist.
5. In the console, note the `userId` from `[fetchStaffContext]` (or from the server log after sign-in). It must match `staff_roles.user_id` in Supabase.

If `staff_roles` exists for a different UUID (e.g. row is `724e2bda-df7a-4db1-a005-36cd937f3592` but auth user is another id), copy the row to the real `auth.users.id`:

```sql
-- Replace OLD and NEW with the UUIDs from Supabase (staff_roles vs auth.users).
insert into public.staff_roles (user_id, role, venue_id, status, is_active)
select
  'NEW_USER_ID_FROM_AUTH_USERS'::uuid,
  role,
  venue_id,
  status,
  is_active
from public.staff_roles
where user_id = 'OLD_USER_ID_FROM_STAFF_ROLES'::uuid
on conflict (user_id) do update set
  role = excluded.role,
  venue_id = excluded.venue_id,
  status = excluded.status,
  is_active = excluded.is_active;
```

You can start editing the dashboard at `src/app/(app)/page.tsx`.

### `SUPABASE_SERVICE_ROLE_KEY` (server-only)

Copy from **Supabase Dashboard → Project Settings → API → `service_role` secret** into `.env.local`:

```env
SUPABASE_SERVICE_ROLE_KEY=your_service_role_secret
```

Restart `npm run dev` after saving. **You must paste this from your own Supabase project** — it is not generated by this repo. Never use `NEXT_PUBLIC_*` for this value.

| Page / feature | Needs service role? | Works without? |
| --- | --- | --- |
| Login, schedule (`/slots`), slot edits | No | Yes (session + publishable key) |
| Venues list / create / edit / delete | No | Yes |
| Venues audit (“Created by”, “Last updated by”) | No* | Yes when `staff_roles.login_username` is set (migrations backfill) |
| Slots “Last edit” labels (superadmin) | No* | Same as venues audit |
| Admins — list staff, change venue scope | No | Yes (superadmin + migrations) |
| Admins — create staff login | **Yes** | List + venue scope only |
| Admins — delete staff login | **Yes** | List + venue scope only |
| Admins — login column for legacy rows | No* | Yes after `login_username` migration; service role fills gaps via Auth Admin |

\*Service role uses Auth Admin (`getUserById`) for any auth user id. Without it, names come from `staff_roles.login_username` via the signed-in superadmin client.

See also `.env.example`.

### Supabase migrations (SQL Editor)

If you do not run `supabase db push` against your project, apply new schema from `supabase/migrations/` manually in **Supabase Dashboard → SQL Editor**.

| Symptom | SQL to run |
| --- | --- |
| Admins: `column staff_roles.login_username does not exist` | [`docs/supabase/staff_roles_login_username.sql`](docs/supabase/staff_roles_login_username.sql) |
| Superadmin cannot list all staff on Admins | `supabase/migrations/20260326100000_staff_roles_superadmin_select.sql` |

After pasting `staff_roles_login_username.sql`, reload **Admins** — usernames and audit labels work without `SUPABASE_SERVICE_ROLE_KEY` for staff rows.
